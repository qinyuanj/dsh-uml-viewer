# 0015 面板交互围绕 DSH 重新设计

**Status**: accepted

本 ADR 修改 [ADR 0011](0011-dsh-plugin-delivery.md) 中「可展开为 `main` 页面」与
「egui 原生窗口在功能对齐后删除」所隐含的界面对齐目标。

## 背景

#30 删除 egui 窗口后，面板的入口仍是从那个窗口照搬来的：标题、提案横幅、返回、状态与
提示由 resident 画进帧里，返回靠左上角 320×44 的坐标热区；刷新质量与隐藏只在右键菜单
里；讨论上下文分散在画布横幅、检查器列表与工具栏按钮三处；面板请求发出后面板上没有
任何反馈，失败只能去对话里找。工具栏与右键菜单是硬编码英文，类卡片是硬编码中文。面板
还自带一套 `main` 页面与 `Expand` / `Close viewer` 按钮，与宿主右侧栏的全屏展示和
标签页关闭重复。

## 决定

- **首要目标是与 companion 的协作可见**：面板请求、讨论上下文、质量运行的结果在面板上
  可见。视觉与控件对齐宿主、适配窄侧栏是约束，不是目标。「行为与 egui 窗口一致」不再
  是约束。
- **窄侧栏是第一设计对象**：面板分三段，全部是 DOM。顶栏放面包屑、讨论上下文切换器、
  搜索与「更多」菜单；画布只画图和跟随指针的悬停弹窗；底部状态条放**请求状态**与状态、
  提示文字。面板实际宽度达到 900px 时图例常驻、类卡片停靠右侧。
- **chrome 离开帧契约**：标题、提案横幅、返回、状态、提示从 `SceneFrame` 中删除，只
  保留悬停弹窗。resident 在 `state` 事件里给面包屑路径（各级 id 与名称）和状态码。
- **讨论上下文切换器**：顶栏的一个下拉，列出源码图与各提案，末尾是新建提案；取代提案
  横幅、检查器里的列表和 `Namespace tree` 按钮。**P** 键保留，等价于选源码图并回到
  树根。
- **取消检查器面板**：「移除箭头」开关进「更多」菜单，图例是从「更多」打开的弹层。
- **选中操作条**：选中类或组件后出现在状态条上方，固定贴底：元素名、打开类卡片或下钻、
  刷新 CRAP、差量 mutation、隐藏；全量 mutation 在次级菜单。外来包只显示名称。右键菜单
  保留为等价的快捷方式。
- **类卡片与源码窗口是抽屉**：从底部升起，一次只显示一个；从类卡片打开成员时内容换成
  源码并可返回。不再有可叠放的多个浮动窗口。
- **取消自有的 `main` 页面与关闭按钮**：全宽形态用宿主右侧栏的全屏展示；删除
  `Expand` / `Conversation` 按钮、`main` 插槽注册与记录会话的 `sessionStorage`。
  `Close viewer` 按钮删除，改为 `registerCloseHandler`：用户关闭标签页时发显式关闭
  （D13），其余情况走撤回宽限。宿主标签页的刷新命令绑到重载，**R** 键保留。
- **请求状态**：宿主按会话持有每个面板请求的状态（已排队、进行中、完成、失败），经
  面板流的一种新事件推给客户端；页面刷新后恢复，DSH 重启后不保留。完成的条目在下一个
  请求开始或 10 秒后淡出，失败的条目留到用户消除。
- **请求状态按 FIFO 归因**：companion 按到达顺序处理请求，宿主把之后的 `uml_*` 工具
  结果归到队首请求。刷新类请求在质量结果 `validResult: false` 时失败、`uml_display`
  成功时完成；隐藏与新建提案凭请求 id 的 `uml_ir` 与随后的 `uml_display` 成功而完成；
  切换讨论上下文在准入成功时完成。一轮对话结束而队首请求未走完，标为失败。
- **不做跳转到对话消息**：DSH 没有公开接口；公开后再加。
- **对话内的工具结果视图**：五个 `uml_*` 工具经 `tool.call.toolview` 显示
  `validResult`、原因与目标；`uml_display` 带「在面板中查看」。它排在面板迁移之后。
- **文案**：DOM 里的文字取自 `locale/*.json`，跟随 `ctx.locale`，中文用 GLOSSARY 的
  规范词。由 resident 排版的文字（类卡片的行、「无数据」、悬停弹窗的行）由客户端在
  建立面板流时传入语言，Rust 侧按语言选字符串表。
- **键鼠**：Ctrl+F、P、R、Ctrl+0、Esc、滚轮平移、Ctrl+滚轮缩放、拖拽、单击选中、
  双击下钻或开卡片全部保留；「更多」菜单项旁标注快捷键。

## 代价

- 范围包含 `crates/scene`、`crates/frame`、帧契约、golden 与 Playwright 用例，不只是
  `packages/client`。
- 不能同时打开多个源码窗口。
- 全屏时对话被盖住，而不是像 `main` 页面那样被替换。
- 用户在面板请求排队期间手动让 companion 运行质量工具，其结果会被归到队首请求上。

## 被否决的方案

- **只换皮**（对齐宿主控件与主题，入口不动）：协作状态仍不可见，这是 egui 窗口就有的
  缺口。
- **chrome 留在帧里由客户端忽略**：golden 与契约继续为不存在的界面负责。
- **每个质量调用都带请求 id 以精确归因**：要改 `docs/companion-rules.md` 与五个工具的
  参数；隐藏与新建提案已带 id，剩余误差只在用户手动插入质量调用时出现。
- **把 resident 排版的文字搬到客户端本地化**：这些文字的宽度参与 Rust 的布局计算，等于
  把排版一并搬走。
- **改用 `dsh-client-ui-primitives`**：DSH 仍禁止加载它
  （[ADR 0013](0013-repository-migration.md) 附录）。
